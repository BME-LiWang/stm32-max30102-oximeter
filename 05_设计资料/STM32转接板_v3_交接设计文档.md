## 1. 项目总览与系统架构

### 1.1 项目目标

这是生物医学信号采集课设的硬件平台：以 **STM32F103C8T6（蓝 pill 最小系统板）** 为核心，插在一块自研"转接板"上，通过板上的标准化插座连接外设，实现：

| 模块 | 器件 | 通信接口 | 插座 | 当前状态 |
|------|------|----------|------|----------|
| 单色 OLED 显示 | SH1106（1.3 寸 128×64，I2C） | I2C1（PB6/PB7） | J2（4P） | 已跑通 |
| 蓝牙透传 | JDY-31（蓝牙 3.0 SPP，从机） | USART2（PA2/PA3） | J4（4P） | 已跑通 |
| 心率血氧 | MAX30102（模块自带上拉） | I2C2（PB10/PB11） | J5（4P） | 板已就绪，手上暂无模块 |
| 姿态六轴（**本次新增目标**） | MPU6050（GY-521 模块） | I2C1 + INT + AD0 | 计划由 J3 引出 | 待改造 |
| 人机交互 | 4 按键 S1–S4、蜂鸣器 BEEP1、板载 LED | GPIO | — | 板上已有 |
| 供电 | XH 2P 输入 + 自锁开关 + 5V/3V3 | — | H24/SW1 | 已工作 |

### 1.2 系统架构（信号流）

```
                         ┌──────────────────────────────┐
   XH 5V 输入 H24 ──SW1──▶│  转接板电源：5V 轨 / 3V3 轨   │
                         └──────────────┬───────────────┘
                                        │ 排母 J1/J7（2×20）
                         ┌──────────────▼───────────────┐
                         │   STM32F103C8T6（蓝 pill）    │
                         │  I2C1 PB6/PB7  I2C2 PB10/PB11 │
                         │  USART2 PA2/PA3  SWD PA13/14  │
                         └───┬───────┬───────┬───────┬───┘
            I2C1(共享)      │       │I2C2   │UART2  │SWD
              ┌─────────────┘       │       │       └─ J6 烧录
        J2 OLED(SH1106)      J5 MAX30102  J4 JDY-31 ──无线──▶ 安卓手机
        J3 备用口(本次改)                       (SPP 9600)
            └─ 计划接 MPU6050（SCL/SDA/INT/AD0）
```

### 1.3 关键设计原则（务必理解）

1. **I2C 靠地址区分设备，不是"一设备一总线"**。多个不同地址的器件可共享同一组 SCL/SDA：
   - SH1106/SSD1306 = `0x3C`（写 `0x78`）/ `0x3D`
   - MAX30102 = `0x57`
   - MPU6050 = `0x68`（AD0=0）/ `0x69`（AD0=1）
   - 三者地址互不相同，共享总线在电气和协议上都合法，**不存在"抢总线"**。
2. **全板没有任何 I2C 上拉电阻**（唯一电阻 R1 是蜂鸣器限流 100Ω）。总线能工作是因为 OLED、MAX30102 等模块**自带上拉**。新增裸器件时必须自己加上拉（典型 4.7kΩ～10kΩ 到 3V3）。
3. **保留 v2 原件不动，所有改动落在 v3**。v3 当前内容与 v2 完全相同（文件大小均为 347275 字节），是干净的改造起点。
4. 用户**强烈偏好"不要我手动操作，你代做"**，最终交付应是成品（改好的工程 + 0 DRC + 同步好的原理图/PCB），而不是教程。

### 4.1 从网络表读出的两个关键事实

1. **I2C1 的 SCL 和 SDA 被分到了两个不同排母**：`PB6_SCL1` 经过 **J1**.6，而 `PB7_SDA1` 经过 **J7**.8。

## 5. 核心任务：给 J3 正式引出 MPU6050 的 INT 与 AD0

### 5.1 需求原文与目标

用户要求：连接 EDA Agent Connector 后，给 **J3 引出 INT 脚和 AD0 脚**，并**同步修改原理图里的 J3 和 PCB 里的 J3**，最终 DRC 清零。

MPU6050（GY-521 模块）需要的有效连接：

| GY-521 针 | 作用 | 目标连接 |
|-----------|------|----------|
| VCC | 电源 | 3V3（模块 2.5～3.3V，勿接 5V） |
| GND | 地 | GND |
| SCL | I2C 时钟 | PB6_SCL1（I2C1） |
| SDA | I2C 数据 | PB7_SDA1（I2C1） |
| AD0 | 地址选择 | 常规接 GND → 地址 0x68 |
| INT | 数据就绪中断 | 一个**空闲 GPIO**（输入，配 EXTI） |
| XCL/XDA | 辅助 I2C（一般不用） | 悬空 |

### 5.2 AD0 与 INT 的设计决策

**AD0（地址脚）——建议固定接 GND：**
- 常规用法 AD0=0 → 地址 `0x68`，与 OLED(0x3C)、MAX(0x57) 不冲突。
- 最简单可靠的做法是在 J3 上把 AD0 针直接连到 GND（板内走线），用户无需任何跳线。
- 若希望保留切换 0x69 的灵活性，可把 AD0 做成"针脚引出 + 旁边放 GND/3V3 选择"，但这增加复杂度，**用户没有这个需求，不建议过度设计**。
- 推荐方案：**J3 增加一个 AD0 针，网络直接并入 GND**，并在文档/丝印标注"AD0=GND, addr 0x68"。

**INT（中断脚）——需要一个确定的空闲 GPIO：**
- MPU6050 的 INT 是可配置的数字输出（可设推挽/开漏、高/低有效、脉冲/锁存），STM32 端配成 GPIO 输入（建议浮空或按模块配置上拉/下拉），并可接 EXTI 实现中断；不接中断也能用**软件轮询**（读 INT 电平或直接周期读寄存器）。
- 选择空闲 GPIO 的**硬性排除项**：
  - 已占用：PB6/PB7（I2C1）、PB10/PB11（I2C2）、PA2/PA3（UART2）、PA13/PA14（SWD 烧录，绝不能占）、4 个 KEY、BEEP。
  - 系统保留：PC14/PC15（外部晶振，蓝 pill 这两脚接 8MHz 晶振）、PC13（板载 LED）、PB2（BOOT1）、NRST、PA15/PB3/PB4（JTAG 复用，虽可重映射但易踩坑）。
- **候选空闲脚（需在 5.3 疑点解决后，结合排母实际可接性最终确定）**：
  - 优先考虑通用、无特殊功能冲突的脚，如 **PA0/PA1、PA4/PA5/PA6/PA7、PB0/PB1、PB12～PB15、PA8～PA12** 等。
  - 注意：这些脚在物理上能否通过 J3 附近的走线连到排母对应针，取决于排母针与蓝 pill 针的真实对应（5.3），**不能只看网络名就定**。

### 5.3 ★★★ 必须先解决的物理映射疑点（核心卡点，勿直接断言板错）★★★

**现象**：把 PCB 排母焊盘按物理 x 排列，用几何中心对齐（底板列 c → 蓝 pill 针位置 q=c+1），并枚举 J1/J7 各自对应蓝 pill top/bot 排、正/反方向（flip）、偏移 offset（范围扩大到 **−12～+12**）的所有组合，**始终没有零错误解，最佳仅 2 个焊盘匹配**。

**最硬的两个矛盾：**
1. J1 的 +5V 焊盘（x=2355，列15）与 GND 焊盘（x=2755，列19）物理间距 **400 mil**；而蓝 pill 下排 5V（位置18）与 G（位置19）相邻仅 **100 mil**。
2. J1 右端 3V3（列18）/ GND（列19）的顺序，与蓝 pill bot 排同位置（G/3.3）顺序相反。
3. 如 4.1 所述，J1 网络同时含只在 top 排的 PA2/PA3 和只在 bot 排的 PB6，单排母无法同时接触两排针。

**两种可能的解释（不要在未核实前直接判定板子接错）：**
- **(A) 数据/理解局限（更可能）**：排母封装的旋转（J1 rot180 / J7 rot0）、针号丝印方向、以及几何中心对齐的某个假设与实际不符，导致从 dump 反推的对应失真。鉴于 **OLED、蓝牙实物均工作正常**，物理连接大概率是对的，问题出在"如何把 dump 坐标映射到蓝 pill 针"的理解上。
- **(B) 板真实接错（可能性低）**：若真实编辑器核实后确实错位，则需重新分配网络。

**为什么不能直接信理论：** 板子上 OLED（I2C1）和蓝牙（UART2）都实测可用，说明至少这些链路的物理针脚是通的、正确的。任何宣称"板错"的理论，都必须先解释"为什么这些外设能正常工作"。

**★ 必须在真实编辑器内执行的核实步骤（接手 agent 按此做）：**
1. 用 `pcb dump`（含 copper 与不含 copper 两版）重新回读，确认与本文档一致。
2. 在 PCB 编辑器中**放大 J1/J7，读取每个焊盘旁的针号丝印**，确认针号方向（哪个是针 1），不要只看坐标。
3. 用**网络高亮**：点击 `PB6_SCL1`、`PB7_SDA1`、`PA2_TX`、`+5V`、`GND` 等网络，观察它们在排母上具体高亮哪个焊盘，以及走线如何连到对应外设。
4. 切换 **3D 视图**，或在排母位置临时放置一个蓝 pill/排针封装做对照，直观确认"针 1 对针 1"。
5. 用一个**确定可用的链路反推**：蓝牙工作 → 蓝 pill PA2 针物理进入 J1 的 PA2 焊盘、PA3 进入 PA3 焊盘；以此两点锚定真实的列→针映射方向，再推广到全部针。
6. 若有实物，最可靠是**万用表通断档**：断电后量排母针到对应外设焊盘的连通性。
7. 在真实映射确定前，**不要写入任何 INT 网络改动**，避免接到错误的针。

### 5.4 J3 针数与针序的待决问题

- 当前 J3 是 1×5P，只有 4 个有效针（GND/3V3/PB6/PB7）+1 空针。要同时引出 SCL/SDA/INT/AD0/GND/VCC，**至少需要 6 个有效针**，因此要把 J3 从 5P 换成 **6P（或更多）排母**，并在原理图同步换符号。
- 针序建议**对齐 GY-521 的常用针序，方便杜邦线直插**。GY-521 一排 8 针常见顺序（从针 1）：`VCC, GND, SCL, SDA, AD0, XDA, XCL, INT`（不同批次可能不同，需以实物丝印为准）。
- 推荐 J3 6P 针序（自定，清晰即可，并在丝印标注）：`GND / 3V3 / SCL(PB6) / SDA(PB7) / AD0(→GND) / INT(→空闲GPIO)`，或按用户手头模块实际针序排列，做到"一根杜邦线不交叉"。
- 换封装后注意：焊盘间距、与周围走线/丝印的间距，移动后必须重新 DRC。

### 5.5 两个用户技术疑点的已裁决结论（背景，避免再被误导）

1. **"J3 接 I2C1 会和 OLED/MPU 抢 PB6/PB7，应改回 I2C2"——该分析错误。**
   - J3 是引出 I2C1 的 5P 备用扩展口；MAX30102 的正式座是 **4P 的 J5，走独立 I2C2**，天然不与 I2C1 冲突。
   - I2C 靠地址区分（0x3C/0x57/0x68 互不相同），共享 I2C1 不是"抢"。
   - 当前板上根本没有 MPU6050；磁盘上也找不到所谓"11-06 版"（只有 v2 和 6 元件简单初版）。**不要去做 J3/J5 互换 I2C 的操作。**
2. **"J3 能接 MPU6050 吗？"——能接。** 现状针数针序不匹配，需杜邦线：SCL→PB6、SDA→PB7、GND、VCC→3V3、AD0→GND；INT 因 J3 未引出只能悬空、用软件轮询。本次改造的目的正是把 INT/AD0 正式做出来。

## 6. 功能模块详细调试档案（含判据与根因）

> 本章记录每个模块"怎么测的、用了什么可信判据、根因是什么、改了什么"，这些方法论可直接复用到 MPU6050 的调试。核心原则（用户偏好 `mem://preference/p1_AQCrplxlvE0`）：**先验证判据本身可信，绝不拿可疑读数去解释现象。**

### 6.1 蓝牙 JDY-31 双向透传（根因：RCC 时钟位写错）

**故障现象**：手机 APP 能连上 JDY-31（SPP），但收不到 STM32 发出的数据，RX CNT 始终为 0。

**排查过程与可信判据：**
1. 不先怀疑蓝牙，先做**纯 GPIO 电平回环**（经验 `stm32-uart-gpio-level-loopback-first`）：把 PA2(TX) 配成输出、PA3(RX) 配内部上拉输入，用"PA3 内部上拉 + 回读 PA2 自身电平"做判据。
   - 具体：PA2 的 ODR 置 1，再读 PA2 的 IDR，正常应回读到自己写的电平；实测回读异常（PA2 FAIL），证明问题在 GPIO 本身，不在 USART/蓝牙。
2. 由此定位到 **RCC 时钟从未开启**。

**根因（关键寄存器事实，务必留档）：**
- `RCC_APB2ENR`（地址 `0x40021018`）的位定义：
  - **bit0 = AFIOEN**（复用功能时钟）
  - **bit2 = IOPAEN**（GPIOA 时钟）
  - bit3 = IOPBEN，bit4 = IOPCEN
- 旧固件误写成 `1U << 0`（只开了 AFIO），**GPIOA 时钟根本没开**，导致 PA2/PA3 以及整个 USART2 的引脚不工作。
- 改成 `1U << 2`（IOPAEN）后，GPIO 回环立刻 SHORT OK，蓝牙随即成功收发。

**修复后正式固件的 USART2 配置（`main_bt_final.c`）：**
- `RCC_APB2ENR |= (1<<2)` 开 GPIOA；`RCC_APB1ENR |= (1<<17)` 开 USART2。
- PA2：复用推挽 50MHz（CRL 对应 4 位 = `0xB`）；PA3：浮空输入（`0x4`）。
- `USART2_BRR = 833`（8 MHz / 9600）；8N1；中断 + 轮询双路径，USART2 中断号 38（NVIC ISER1 bit6）。
- 接收处理：过滤 `\r`，`\n` 转空格，只保留可打印 ASCII（32–126），15 字节环形缓冲。

**JDY-31 模块事实（避免再踩坑）：**
- 蓝牙 **3.0 SPP（经典蓝牙，不是 BLE）→ iPhone 连不上**，只能安卓；用户手机是安卓，正常。
- 手册标称 3.6～6V，但 **3V3 实测可稳定工作**（J4 的 VCC 就是 3V3，无 5V）。
- 默认参数：9600 波特率、8N1、仅从机模式、配对码 `1234`。
- MAC：`XX:XX:XX:XX:XX:XX`；广播名：`JDY-31-SPP`。
- 历史悬而未决：JDY-31 四针实物针脚定义未逐一核对（接好能用，但文档化时建议补）。

### 6.2 OLED SH1106 识别（边框四角对比法 + 列地址偏移）

**问题**：无法读 ID，需确认 OLED 控制器是 SSD1306 还是 SH1106（二者初始化、列地址不同）。

**可信判据（经验 `oled-controller-ssd1306-vs-sh1106-border-test`）：**
- 烧一个"全屏边框 + 四角实心块"的对比固件，分别用列起始偏移 OFFSET 0 和 OFFSET 2 刷同一画面：
  - **OFFSET 0**：四角块缺失、边框不闭合；
  - **OFFSET 2**：四角完整、边框闭合。
- 由此判定控制器是 **SH1106（1.3 寸 128×64）**。

**根因/差异：**
- SH1106 的显示 RAM 是 **132 列**，而屏幕只露出 128 列，存在 2 列水平偏移。
- `oled_flush` 里设置**低列地址（low column address）要从 `0x00` 改为 `0x02`**，画面才对齐、不残边。
- 相关现象：正常显示时最右边缘若出现一列规则亮点，是驱动 IC 132 列 RAM、固件只写 128 列导致的边缘残留（经验 `stm32-oled-edge-column-residue`）。

**I2C 配置：**
- I2C1，PB6=SCL/PB7=SDA，**100 kHz**（CCR=40、TRISE=9，APB1=8MHz），地址 0x3C（写 0x78）。
- 引脚配复用开漏；模块自带上拉，底板无上拉。

### 6.3 硬件 I2C 的跨板对照与"ACK 通但数据刷不进"

- 历史上遇到"从机地址 ACK 正常、数据阶段超时、屏空白"，用**速率核对 + 换板对照（A/B test，单变量）**区分是电气问题还是芯片外设问题（经验 `stm32-hw-i2c-across-boards-ab-test`、`hw-i2c-ack-but-data-stall`、`hw-fault-attribution-verify-config-single-variable`）。
- 教训：换板/换驱动/改速率后现象消失，要避免连续错误归因；一次只改一个变量。
- 曾出现"400kHz + 10k 上拉 → 亮一下即熄"，说明高速 + 弱上拉/开漏在该链路不可靠，**本项目统一回到 100kHz**。
- 极端情况下软件推挽 I2C 可作兜底，但当前硬件 I2C 已稳定，不需要。

### 6.4 MAX30102（板已就绪，待模块）

- 正式座 **J5（4P），走独立 I2C2：PB10=SCL2、PB11=SDA2**，地址 0x57，与 I2C1 完全独立。
- 模块**自带上拉**，底板无需加上拉；参考工程在桌面 `02-心率血氧仪\01-MAX30102工程源码`（标准库，含 HARDWARE/MAX30102、OLED、exti 等）。
- 用户手上暂无该模块，软件可先参考例程移植，硬件链路已具备。

### 6.5 MPU6050（本次新增，调试预案）

- 地址 0x68（AD0=0）/0x69（AD0=1），I2C 最高 400kHz，本项目跑 100kHz 即可。
- 上电后先验证 WHO_AM_I 寄存器（寄存器 117/0x75），回读值应为 `0x68`，这是"通信真的通了"的可信判据（类比之前先验证判据）。
- INT 行为通过寄存器配置：INT_PIN_CFG（0x37，开漏/推挽、有效电平、锁存）、INT_ENABLE（0x38）；数据就绪在 INT_STATUS（0x3A）。
- 建议调试顺序：① 回读 WHO_AM_I → ② 配置电源/时钟（PWR_MGMT_1 0x6B，解除休眠）→ ③ 读原始加速度/陀螺仪验证数据变化 → ④ 再配 INT/EXTI。
- 无中断时先软件轮询跑通，再切中断，符合"先建立可信判据再深入"的一贯方法。

## 9. EDA Agent Connector 工具链使用指南

### 9.1 架构与调用链

```
Skill/CLI (easyeda.exe)  ──HTTP──▶  Go daemon (127.0.0.1:60832)
                                        │ WebSocket
                                        ▼
                          EDA Agent Connector (扩展, 唯一调用 eda.*)
                                        │ 官方 eda.* API
                                        ▼
                          嘉立创 EDA 专业版真实编辑器
```

- 连接器是系统中**唯一直接调用官方 eda.* API** 的组件；所有写操作最终都落在嘉立创官方插件能力上。
- 前置条件：EDA 内已安装连接器、已开启"**允许外部交互**"、daemon 已启动（当前全部满足，故能连通）。

### 9.2 开工前检查（每次会话先做）

```powershell
& "easyeda" health
```
确认：daemon ok、≥1 窗口已连接、CLI/daemon/connector 版本一致（当前均 v1.16.0）、EasyEDA 版本满足基线。
若 daemon 未运行：`easyeda daemon start`；版本对齐检查：`easyeda update --check`。

### 9.3 本任务相关命令（语法以 `--help` 现读为准，勿凭记忆）

**只读/回读（写前后都要用）：**
| 命令 | 用途 |
|------|------|
| `easyeda doc ls` | 列出工程文档 |
| `easyeda pcb list` / `pcb dump` | 列出/导出 PCB 元件与焊盘几何 |
| `easyeda pcb drc` | 跑 DRC，返回归一化违规 |
| `easyeda pcb nets` / `track-list` / `via-list` | 网络/走线/过孔 |
| `easyeda sch read` / `sch list` / `sch pages` | 原理图语义快照/元件/页面 |
| `easyeda board`（board-info） | 原理图↔PCB 绑定关系 |

**写操作（改造会用到，务必带 `--doc` 锁定文档避免切错页）：**
| 命令 | 用途 |
|------|------|
| `easyeda sch place` / `sch replace` / `rebind-symbol` | 放置/换型号/换符号 |

| `easyeda pcb add-component` | 放置+连接一个封装（import-changes 的可用替代） |

| `easyeda pcb save` / `sch save` | 保存到磁盘 |

### 9.4 安全操作纪律（重要）

1. **写操作前先 `dump`/`read` 回读**，并全程用全局 `--doc <uuid>` 或 `--project <uuid>` 锁定目标文档，防止"前台页面不是目标页"导致写错地方。
2. **写操作后立即回读 + DRC 验证**，确认无误再 `save`；不要在结果未确认时连续发多个写操作。
3. 优先用 `pcb add-component` 而非 `import-changes`（后者在历史使用中易带出额外变更）。
4. 自动布线/自动修复类命令要谨慎：历史上 `autoroute` 修复移动后的 J7 报"100% 完成"但实际 DRC 19 个间距错误（见第 10 章），**不能只看命令自报成功，必须以 DRC/回读为准**。
5. 本环境 Bash 不可用，**所有命令走 PowerShell**；Python 3.13 可用于离线分析。
6. 改动只落在 v3；保存前确认当前文档 uuid 正确，避免误覆盖 v2。

## 10. 已证伪 / 做不通的方向（不要再尝试）

| 方向 | 结论 | 证据 |
|------|------|------|
| 蓝 pill 两排针间距是 700mil，需改板 | **错误，真值 600mil=15.24mm** | KiCad 测绘封装 15.24mm + 外壳 15.2mm + 用户尺寸图，三源交叉验证 |
| 用自动布线修复移动后的 J7 | **不可行** | 命令报 100% 完成，实际 DRC 19 个间距错误（焊盘/钻孔到导线 0mil 短路） |
| J3 接 I2C1 会和 OLED/MPU"抢"PB6/PB7，应与 J5 互换 | **错误** | I2C 靠地址区分；MAX 正式座 J5 走独立 I2C2；无 11-06 版、当前无 MPU |
| 400kHz + 10k 上拉 | **不可靠** | 屏亮一下即熄，回到 100kHz 才稳定 |
| "SHORT NG = 线没通" | **错误推断** | PA2 自读判据证伪，真因是 GPIOA 时钟未开（RCC 位写错） |
| 中断向量表错误 | **已排除** | 向量表经验证正确 |
| JDY-31 当 BLE 用 / iPhone 连接 | **不可能** | 蓝牙 3.0 SPP 经典蓝牙，非 BLE，iPhone 不支持 SPP |
| 给 JDY-31 必须供 5V | **不成立** | 手册 3.6–6V，但 3V3 实测稳定工作 |
| 全板有 I2C 上拉 | **错误** | 唯一电阻 R1 是蜂鸣器 100Ω；总线靠模块自带上拉 |

**ST-Link 相关踩坑（烧录异常时）：**
- ST-Link 报 "Unable to get core ID / No device found" 多为调试会话挂死，**拔插 USB 即可恢复**（经验 `stlink-swd-session-hang-recover-by-usb-replug`）。
- CubeIDE 报 GDB server 失败但 CubeProgrammer CLI 能烧，多为磨字/克隆芯片 ID 校验问题，用 CLI 烧即可，不必改走串口。
- CubeIDE Makefile 手工编译可能"make 成功但 hex 未更新"，烧的是旧固件，注意确认 hex 时间戳。

## 13. 给接手 Agent 的标准执行流程与验收标准

### 13.1 推荐执行顺序（严格按此，先读后写）

```
阶段0 环境确认
  health → 确认 daemon/connector/版本/窗口；确认打开的是 v3 工程

  （此步未完成前，禁止写 INT 网络）
阶段3 定方案
  敲定 INT 空闲 GPIO、AD0→GND、J3 6P 针序
阶段4 改原理图（先 SCH，后 PCB）
  换 6P 符号 → place/connect 新增 INT、AD0 → sch drc 清零 → sch save
阶段5 改 PCB
```

### 13.2 验收标准（逐条满足才算完成）

- [ ] **物理映射已在真实编辑器核实**，INT 所选 GPIO 经"针号丝印 + 网络高亮 + 可用链路反推"三重确认，且不与 SWD/晶振/已用脚冲突。
- [ ] J3 在原理图与 PCB 中**针数一致、针序一致、网络一致**（同步无偏差）。
- [ ] AD0 正确接 GND（地址 0x68），并在丝印/文档标注。
- [ ] INT 走线连到确定的空闲 GPIO，走线满足线宽/间距规则。
- [ ] **原理图 DRC = 0 且 PCB DRC = 0**（以编辑器/`drc` 实时结果为准，不信命令自报的"100%"）。
- [ ] 改动只落在 v3，v2 原件未被修改；保存后重新 `dump`/`read` 回读确认落盘。
- [ ] 若新增裸 I2C 器件（非模块），已补 4.7k～10k 上拉；本任务用 GY-521 模块则其自带上拉，需确认。
- [ ] 交付物包含可打开的 v3 工程路径与完整验证说明，用户无需手动操作。

### 13.3 隐含设计想法（用户未明说，但应主动满足）

1. **最小改动、不过度设计**：AD0 固定 GND 即可，不必做地址切换开关；INT 单脚引出即可，不预留多余功能。
2. **可制造性**：换封装后焊盘、过孔、走线满足实时规则；丝印位号不与焊盘/针号重叠；针号方向清晰。
3. **易用性**：J3 针序尽量对齐 GY-521 实物，做到杜邦线直插不交叉；VCC/GND 位置固定、降低接反风险。
4. **可调试性**：保留 PC13 LED 作状态指示；固件先建立 WHO_AM_I 等可信判据再深入；保留软件轮询作为中断失效时的兜底。
5. **电气稳健**：统一 100kHz I2C；3V3 电平；注意多外设共用 3V3 的总电流；新增上拉要到 3V3 而非 5V。
6. **可追溯**：网络命名沿用现有 `PB6_SCL1` 风格；新网络（如 INT 对应 GPIO、AD0）命名清晰；改动可回读、可审计。
7. **风险前置**：任何"板错/接错"的判断，必须先解释"现有 OLED/蓝牙为何能正常工作"，否则视为未证实，不得据此改板。
