# MAX30102（八针黑色 MH-ET LIVE 板）旧板验证报告

- 日期：2026-11-15
- 被测对象：八针黑色 MH-ET LIVE / MAX30102 模块（3.3V 逻辑，丝印 `GND RD IRD INT` + `VIN SDA SCL GND`）
- 测试平台：旧 STM32F103C8T6 蓝 pill 最小系统板（同时在跑 SH1106 OLED + JDY-31 蓝牙）
- 结论：**模块本身完全正常，可以正常使用。** 之前的“NO SENSOR FOUND”全部是固件 bug，与模块、接线、供电无关。

## 一、最终读数（硬件 I2C2，实时 RAM）

| 变量 | 值 | 含义 |
|---|---|---|
| `dbg_rep` | `0x5A011502` | 魔数 0x5A ✓、总线=1（**硬件 I2C2 命中**）、PART_ID=`0x15` ✓、OLED 在位 ✓、ACK 成功 |
| `PART_ID` 回读 | `0x15` | MAX30102 正确型号 ID |
| 配置回读 | `mode=0x03`、`spo2=0x27`、`fifo=0x2F` | 三个关键寄存器均写入成功 |
| 空载 IR / RED | `4351` / `1697`（18bit 原始计数） | 环境光/暗电平，正常 |
| **盖手指后 IR / RED** | **`130559` / `118221`** | 相对空载跳变 30~66 倍，说明 LED 点亮、光电二极管正常接收反射光 |
| `buf_idx` | 持续递增（0x24→0x58） | 采样流在持续跑通 |
| `dbg_lv` | `0x00000303` | 浮空读=11、内部上拉读=11、开漏拉低读=00 → 外界有上拉、引脚驱动正常 |

## 二、根因：本次定位到 3 个固件 bug（都已修复）

1. **`i2c_init` 中 SWRST 时序错误（本轮最关键）**
   原写法是 `CR1=SWRST` 之后才写 `CR2/CCR/TRISE`。SWRST 置位期间这些配置被丢弃，CCR/TRISE 实际为 0，
   SCL 时钟根本出不来，因此 START 条件发不出去（`i2c_ping` 返回码 1 = SB 位超时）。
   正确顺序：`CR1=0`（PE=0）→ `CR1=SWRST=1` → 等一拍 → `CR1=0`（退出 SWRST）→ 写 `CR2/CCR/TRISE` → `CR1=PE`。
   修好后 `i2c_ping` 一次命中 0x57，PART_ID 立刻读到 0x15。

2. **GPIO 先配成 AF 开漏、ODR 却为 0，等于开机把 PB10/PB11 主动拉低**
   I2C2 一使能就看到“总线忙”，SB 永远置不起来。修复：配 AF 之前先 `GPIOB_ODR |= (0x03<<10)`。

3. **FIFO 读法错误：一个样本一个 I2C 事务，读指针不推进**
   实测表现为：连读 16 次返回值一字不差、`FIFO_WR_PTR` 恒为 0、`OVF` 却在涨。
   正确做法是**在一次事务里连续突发读**（本固件一次读 32 样本 = 192 字节，按约 50 样本/秒的节奏取），
   读指针才会推进，数据才有波形。

附带修掉的历史 bug：旧软 I2C 的 `si_start/si_stop/si_rbyte` 时序反了（这才是早期“四组软 I2C 全 NACK”的真正原因）。

## 三、接线（当前实测可用的接法）

模块只用 4 根线，**不接 INT 也能正常工作**（本固件纯轮询 FIFO）：

| MAX30102 模块 | 蓝 pill |
|---|---|
| VIN | 3V3 |
| GND | G |
| SCL | **PB10** |
| SDA | **PB11** |

> 注意：卖家例程用的 PB7/PB8 + PB9(INT) 是**另一套**分工（软件 I2C），不要照它的表接线。
> 模块自带的 4.7k 上拉已经够用，旧板无需外加电阻。

## 四、怎么复现这个验证

```powershell
# 1) 烧录（本报告同目录的固件）
D:\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe -c port=SWD freq=1000 `
  -w "./固件_MAX30102_可用版_20261115.hex" -v -rst -run

# 2) 关键：等约 10 秒（开机自检页要停 6 秒），然后必须用 hotplug 免复位连接读活值
Start-Sleep -Seconds 10
D:\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe -c port=SWD freq=1000 mode=hotplug -r32 0x2000047C 1
```

**血的教训（务必记住）**：普通 `-c port=SWD freq=1000 -r32 ...` 每次连接都会软复位并 halt 内核，
读到的是上一次运行遗留的 RAM，会得出完全错误的结论（本轮就因此误判过“模块没电”“SCL/SDA 插反”）。
要么加 `-run` 后再用 `mode=hotplug` 连接，要么看 `dbg_cnt` 心跳有没有在涨。

## 七、其他 agent 改动引入的问题与修复

### 现象
- OLED 全黑（`dbg_rep` 的 OLED 位 = 0），复位 3 次全部为 0，其中一次还退化到软 I2C 兜底（`0x5A0B0000`，bus=11、ID=0）。
- MAX30102 数值冻结：5 秒内 `max_ir_raw`/`max_red_raw` 一字不变，`buf_idx` 5 秒只进 15 个样本（约 3 样本/秒），`spo2_valid=0`。

### 根因 1：FIFO 读取被回退成"按 WR/RD 指针读"
改成"读 WR_PTR/RD_PTR 算积压量 n，n==0 时每 32 次循环兜底读 1 个样本"。
实测 WR_PTR 恒为 0，永远走兜底路径，每 32 次循环才 1 个样本；且单样本事务读指针不推进，数值冻结、血氧拿不到有效信号。
这是已经证伪的旧写法，不能回退。已恢复为"每 32 次循环做一次 32 样本(192 字节)突发读"。

### 根因 2：OLED 初始化偶发失败（黑屏）
1) `gpio_init` 里 PB6/PB7 配成 AF 开漏前没有先置高 ODR（PB10/PB11 是置过的），上电瞬间等于把 OLED 总线主动拉低，首写易失败；
2) OLED 初始化只试一次（0x78 失败后试 0x7A），没有重试、没有重配总线。
修复：`GPIOB_ODR |= (0x03U << 6)` 先置高；初始化改成最多 6 次重试，每次重试前 `delay_ms(60)` 并 `i2c_init(&bus1)` 清 BUSY/ADDR 状态。

### 根因 3（不是 bug，但会让人误判）
空载时 IR/RED 是稳定的环境光 DC（约 3327 / 1625），不是死机；只有按压时才跳到十几万。

### 保留的其他 agent 改动（判断正确，已保留）
- `calc_spo2` 按 `buf_idx` 环形顺序遍历缓冲（原来按 0..99 顺序读，波形断裂，过零检测失效）——真 bug 修复。
- `clear_vitals()`：无有效信号时清零，避免上位机显示旧值。
- `bus1` 兜底成功时补 `max_bp = &bus1`——真 bug 修复。
- 开机自检页 6s→2s、`page_idx=0`（回主界面）、主循环删除调试探针——产品化取舍，可接受。
