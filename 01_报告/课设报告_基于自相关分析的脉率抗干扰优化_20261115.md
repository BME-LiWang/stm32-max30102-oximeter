# 基于自相关分析的脉率抗干扰优化（课设报告素材）

> 适用对象：STM32F103C8T6（8 MHz，未开 PLL）+ MAX30102（8 针 MH-ET LIVE 模块，I2C1 = PB6/PB7，50 kHz）
> 数据采集：探头 100 sps、18 bit、411 µs 脉宽，片上 2 次采样平均 → 输出 **50 Hz**
> LED 电流：红光/红外各 10.4 mA（寄存器 0x34），指腹按压时 IR 直流 ≈ 2.0×10⁵ counts

## 1 问题现象

Maxim 官方参考算法（时域峰间隔法）在低灌注条件下给出明显偏高的脉率。同一段 8 s 窗口内：

- Maxim 算法：平均峰间隔约 27 个样本（50 Hz 采样）→ **PR ≈ 111.9 bpm**
- 波形本身：相邻“大峰”间距忽大忽小，峰高在 300~1000 counts 之间交替（大峰后约 0.2~0.4 s 出现一个次级波峰）
- 频域：DFT 主峰 1.75 Hz（105 bpm），但该峰是**二次谐波**

根因：指腹按压偏轻时，PPG 的**重搏波（dicrotic notch / 反射波）**幅值升高，经一阶差分 + 5 点汉明窗后形成独立极值，被 `maxim_find_peaks`（最小间距 8 点）当成一次独立心跳，平均峰间隔被压到约一半，PR 直接翻倍。这是时域峰检测的固有缺陷，不是接线或传感器故障。

## 2 判据自检：为什么可以断定“翻倍”而不是“真的 105 bpm”

对同一段去趋势信号计算自相关 r(lag)（50 Hz 采样，lag 单位＝20 ms）：

| lag | 对应 PR | r |
|---|---|---|
| 26 | 115 bpm | 0.214 |
| 30 | 100 bpm | **−0.093** |
| 57~61 | 49~53 bpm | **0.34 ~ 0.51** |
| 87 | 34 bpm | 0.353 |

若真实周期是 30 个样本，则半周期（lag=15）应显著负相关、lag=30 应显著正相关；实测 **lag=30 为负相关**，而 lag≈57~61 才是稳定的正峰。这说明主周期是 57~61 个样本（**约 50~53 bpm**），1.75 Hz 的谱峰来自“每个心动周期出现两个波峰”的谐波结构。判据本身先被验证过，才用它来修正算法。

## 3 混合（Hybrid）算法

### 3.1 前置：去趋势（必须做）

自相关对基线漂移极其敏感，先去趋势否则主峰会偏向 lag=0。实现上不拟合直线，改用**滑动均值高通**（更省算力）：

```
x[i] = IR[i] − mean(IR[i−8 … i+8])      // 17 点滑动均值，端点夹紧
```

去趋势后残余幅值 |x| ≤ 1036 counts（未去趋势时“峰峰值”大头是漂移）。若 max|x| > 25000（手指刚放上/移开的过渡窗）直接放弃本窗，避免给出假周期。

### 3.2 自相关

为省掉 111 次开方，用能量均值代替几何均值：

```
r(lag) = 2·Σ x[i]x[i+lag] / ( Σx[i]² + Σx[i+lag]² )
```

全 int32 乘加（残差已限幅，无溢出），lag ∈ [18, 80]（50 Hz 下对应 37~166 bpm），取 **r 的全局最大值**，并要求 r ≥ 0.30。早期实现取“第一个高于门限的局部极大”，实测会被噪声小峰抢占，显示值在 20~30 bpm 范围内来回跳，故改为全局最大值。

### 3.3 仲裁规则（两道防线，不删 Maxim）

每个窗口都跑一次自相关，用它做仲裁者：

| 条件 | 采用 | 说明 |
|---|---|---|
| Maxim 无效（hr_valid=0） | 自相关 | 峰检测失败 |
| Maxim 落在 1.4~3.0 倍自相关结果之间 | **自相关**，屏显 `[AC]` | 判为重搏波多计 |
| 两者接近，或 Maxim 反而更低 | Maxim | 时域法更精确、更省电 |
| 自相关无效（r<0.30） | Maxim | 兜底不成立 |

稳定性处理：自相关结果先做**最近 3 次中位数**滤波，再按“每秒最多变化 10 bpm”限速平滑，避免算法切换瞬间数字跳变。

### 3.4 关键参数

| 参数 | 取值 | 依据 |
|---|---|---|
| 采样率 | 50 Hz（100 sps × SMP_AVG=2） | 噪声降 √2，脉率上限 166 bpm 仍够 |
| 窗口 | 400 点 = 8 s | 4~7 个心动周期 |
| 刷新 | 每窗滑 50 点（1 s） | 1 Hz 更新 |
| 去趋势窗 | 17 点（≈340 ms） | 高通零点远高于脉率基频 |
| lag 范围 | 18~80 | 37~166 bpm |
| 门限 | r ≥ 0.30 | 实测稳态 r≈0.34~0.51 |
| PR 换算 | PR = 60·fs/lag = **3000/lag** | 50 Hz 采样 |

## 4 实测结果

### 4.1 效果

| 指标 | 优化前（Maxim 单独） | 优化后（Hybrid） |
|---|---|---|
| PR | 111.9 bpm（翻倍） | **52.6 bpm**（lag=57） |
| SpO₂ | 97 % | 97 % |
| PI | 1.69 % | 4.35 %（LED 10.4 mA + 2 次平均后） |
| 去趋势残余幅值 | ±302 counts | ±1036 counts |
| 显示稳定性 | 曾停在 193 bpm 不动 | 连续 5 s 保持 52.6，跳动 ≤ ±10 bpm/s |

### 4.2 耗时（8 MHz 软浮点，实测而非估算）

由内核 DWT 周期计数器直接测得单次自相关调用：

- 1,507,291 个内核周期 → **188 ms**（TICK_PER_MS = 8011）
- 折算到 72 MHz 主频约 **21 ms**
- 占空比：1 s 调用一次 ≈ 19 % CPU；FIFO 深度 32 样本 = 640 ms 缓冲，不丢样本
- 代码/内存代价：text 23.6 KB，bss 12.2 KB（新增 608 B 自相关缓冲 + 12 B 中位数历史）

> 说明：DeepSeek 建议中“72 MHz 几毫秒”的前提在本板不成立（PLL 未开，实测 HCLK=8 MHz），故报告按 188 ms 实测值给出，并同时给出 72 MHz 折算值。

## 5 可写进报告的结论段（可直接引用）

> 针对 Maxim 官方时域峰间隔法在低灌注下将重搏波误判为独立波峰、导致脉率翻倍的问题，本设计在嵌入式端引入去趋势自相关作为仲裁与兜底。算法先以 17 点滑动均值做高通去趋势，再在 lag ∈ [18,80]（37~166 bpm）内计算能量归一化自相关系数，取全局最大值并以 r ≥ 0.30 为可信门限；当峰间隔法失效或其结果是自相关结果的 1.4~3.0 倍时，改由自相关给出脉率（PR = 3000/lag，50 Hz 采样）。实测同一窗口内 Maxim 输出 111.9 bpm，自相关输出 52.6 bpm，且半周期自相关为负（r(lag=30) = −0.093），证实主周期确为 57~61 个样本，翻倍判据成立。自相关单次耗时 1.5×10⁶ 周期（8 MHz 下 188 ms，折算 72 MHz 约 21 ms），1 Hz 调用一次，对实时性与 FIFO 读取无影响。

## 6 局限与后续

1. **缺独立心率参照**：52.6 bpm 与 111.9 bpm 的取舍由波形判据（半周期反相关）支持，仍建议用指夹血氧仪/手表复核一次静息心率，作为报告里的第三方对照。
2. **起点延迟**：窗口 8 s，上电后约 8 s 才出第一个值；如需要更快，可把窗口缩到 200 点（4 s），代价是低频分辨率下降。
3. **极低灌注仍会失效**：去趋势残余若长期低于 ~200 counts，r 无法越过 0.30，此时保持上一次数值（不清零）。
4. **RED 通道未做坏字节修复**：实测 400 点中仅 2 点，暂不处理。
5. **上位机看不到 `[AC]`**：标识只做在 OLED（PR 数值右侧）。若要在上位机显示，需扩展帧类型并同步修改 `FRAME_LENGTHS`，属下一步工作。
