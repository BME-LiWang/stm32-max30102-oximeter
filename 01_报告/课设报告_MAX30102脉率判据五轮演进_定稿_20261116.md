# MAX30102 脉率判据的五轮演进与分辨率极限（课设报告 · 定稿）

> 适用对象：STM32F103C8T6（已开 PLL，HCLK 72 MHz / APB1 36 MHz）+ 8 针 MH-ET LIVE MAX30102（I2C2 = PB10/PB11，纯轮询 FIFO，不接 INT）
> 采样口径：探头 100 sps、18 bit、411 µs 脉宽，片上 SMP_AVG=2 → **输出 50 Hz**
> LED 电流：RED/IR 各 10.4 mA（寄存器 0x34），按压时 IR 直流 ≈ 1.9×10⁵~2.1×10⁵ counts、峰峰值 1.6~2.1×10³ counts
> 本文替代旧稿《脉率判据的分频错误排查与频域主判据改造》（2026-11-15）与《基于自相关分析的脉率抗干扰优化》：前者的"频域为主判据"结论已被第四版、第五版实测推翻，后者的"真实心率 52.6 bpm、Maxim 翻倍"结论属分频错误、已被第三方参照证伪。

## 1 问题的实际形态：不是"翻倍"，是"分频"

早期版本用自相关在 lag ∈ [18,80] 内取**全局最大**，给出 52.6 bpm，并据此判断"Maxim 的 105~112 bpm 是把重搏波多计了一次"。这个判断错在**判据本身没被验证**。

外部参照（同一时段、静息、坐姿）：

| 参照源 | 读数 | 均值 |
|---|---|---|
| 小米手环（连续三次） | 93 / 87 / 96 bpm | 92 |
| 手动摸脉搏 15 s 计 22 次 | 88 bpm | 88 |
| 干净窗口 DFT 主峰 | 1.50 Hz → 90.0 bpm | 90 |

真实心率 ≈ 88~93 bpm，对应周期 50 Hz 下 **lag ≈ 32~34**。算法给出的 52.6 bpm 对应 lag ≈ 57，正好是**两个心动周期**，即经典的分频（倍周期锁定 / subharmonic locking）。

### 1.1 为什么会锁到 2 倍周期

对同一段干净窗口（IR 193,944~195,604，p2p 1660，按压稳定）算自相关剖面：

| lag | 对应 PR | r |
|---|---|---|
| 32 | 93.8 bpm | **0.280**（真基频） |
| 62 | 48.4 bpm | 0.226 |
| 64 | 46.9 bpm | 0.235 |
| 109 | 27.5 bpm | 0.215 |

基频峰**存在但弱**（0.280），而 2 倍周期处（0.226~0.235）与之只差 0.05。此时：

1. 门限设在 r ≥ 0.30 → 真基频被门限挡掉，退而求其次落到 2 倍周期；
2. 即使门限降到 0.20，若再取"全局最大"，HRV 又把短 lag 段（32~38）抹平，哪个点最大变成随机事件。

这就是"自相关在 90 bpm 信号上不可靠"的物理原因：**心率变异使基频峰变宽变矮，2 倍周期峰相对变高**。

### 1.2 排查顺序（方法论，可单独成节）

1. **先拿外部参照**，不要用算法输出自证：手环 + 手数 + 频谱三源交叉，确认真实值落在 88~93；
2. **再验判据本身**：看半周期反相关、看多 lag 剖面（上表），确认"lag≈57 的峰比 lag≈33 高"这一现象确实存在；
3. **最后才谈修正**：把"取全局最大"这种无先验判据，换成带生理约束 + 相干积累的判据。

> 教训：读数异常时先证伪判据，再解释物理现象。拿可疑读数去推导"Maxim 翻倍"的结论，会得到一份严密但完全错误的报告。

## 2 基准的修正：心率本身一直在动

前三章的参照都建立在"真实心率是一个固定值（88~93）"这个隐含假设上。这个假设后来被手机自带心率功能推翻：

| 手机页面 | 读数 | 口径 |
|---|---|---|
| 今日概览·心率范围 | **68~93 次/分** | 当日波动区间 |
| 今日概览·平均心率 | **74 次/分** | 全天平均 |
| 单次测量（同时段对照用） | **77 次/分** | 瞬时 |
| 检测说明页 | "平均心率误差 <3 次/分"；"**压力过大会减少手指中血液流动，导致结果不准确**" | 官方口径 |

由此确立三条新前提：

1. 静息心率在 68~93 之间本来就会波动，**不能把某一个读数（如 92）当作恒定真值**，否则会把"跟随时变心率"误判成"算法漂移"；
2. 手机厂商自己也承认压力会改变指端血流并影响结果——这与本设计在 PI 与判据可信度上的发现（§3.3、§5.1）是同一件事，可作为外部佐证引用；
3. 验收方法必须改为**同一时刻对照**：手机测一次 → 10 秒内立刻上板采 60~90 秒，用心率在十几秒内不会明显变化这一前提来锁定基准。

### 3.1 原始版为什么 0/3：输出被频域搜索区间端点夹持

三轮实测的 PR 极值 65 与 126 bpm，恰好等于 `SP_K_LO=8`（60 bpm）与 `SP_K_HI=17`（127.5 bpm）附近的边界行为；再加上摆动步长恒为 10 bpm（正是 `pr_slew` 的上限），可以判定：**判决长时间贴在搜索区间两端**，输出不是测量结果而是区间端点。叠加 `sp_sm` 的 0.7/0.3（时间常数约 24 s）记忆，压力一变就要几十秒才能爬回来。

### 3.2 第二版为什么失败：更长的记忆 + 惯性会锁死错误初值

第二版把平滑系数改成 0.85/0.15，等效记忆约 40 s，并给峰位加了 ±2 bin 的惯性、PI>15 时冻结输出。结果是过压段（PI 20）算出的 61~68 bpm 被记忆锁死，整个 43 帧采集期内都没收敛回来（SD 11.01）。**结论：用"更长平滑 + 峰位惯性"压抖动，等于把错误初值一起固化**。这一版整体回退。

### 3.3 第三版暴露的真实病灶：PR ≈ 60 + 7×PI 的线性耦合

第三版回到 0.7/0.3 平滑与 15 点中位数后，"稳"是稳了，但稳在错的地方：

| PI 区间 | 输出的 PR |
|---|---|
| 2.9~3.5% | 68~70（稳，但错） |
| 4.9% | 88 |
| 5.9% | 98~103 |

PR 与 PI 呈**近似线性**关系（PR ≈ 60 + 7×PI）。这不是心率变化，而是**频谱判据在测波形形态而不是心跳周期**：按压越重，波形被削顶/展宽，谐波能量分布随之改变，主峰位置被带走。这条证据直接否定了"频域为主判据"的路线。

同期还定位到一个硬伤：**频域 bin 宽 7.5 bpm**（400 点 @50 Hz，见 §6.1），判决只能落在 82.5 / 90 / 97.5 三个离散点上，本就不可能分辨 77 与 83。

### 3.4 第四版转向自相关优先的依据

干净窗的实测：lag=32 → 93.8 bpm，与手环均值 92、手数 88、DFT 1.50 Hz（90.0）一致；而频域在同一个人、同一根手指下随压力漂移。于是把仲裁规则改为：

```
若 PI ≥ 2.5%  → 主判据用自相关（波形足够好，时域周期最可靠）
否则          → 主判据用频域（弱灌注下频域相干积累更稳）
```

第四版的长采集（long1）首次出现 **PR = 91 连续 22 帧**（PI 2.6~7.8），与真实心率吻合。但同一轮里 192~212 s 锁 75~79、232~239 s 锁 83，**同一个 PI 下出现不同值**——这不是压力耦合，而是判决在 lag 33 / 36 / 40 三个邻近峰之间切换（对应 91 / 83 / 75 bpm），再被 `pr_slew`（±5 bpm/帧）拖成缓慢漂移的假象。

### 3.5 第五版：lag 域投票

针对"单窗自相关在相邻 lag 上跳"这一病灶，在自相关段加入 lag 域投票：

```c
/* lag_ring[15]: 最近 15 个有效窗的 lag；有效条件 lag>0 && ac_r>=0.18 且 35≤PR≤140 */
for (a = 0; a < lag_n; a++) {
    cnt = 0;
    for (b = 0; b < lag_n; b++)
        if (abs(lag_ring[b] - lag_ring[a]) <= 1) cnt++;   /* ±1 聚簇 */
    if (cnt > best_cnt ||
        (best_cnt && cnt + 1 >= best_cnt && lag_ring[a] < best_lag))
        { best_cnt = cnt; best_lag = lag_ring[a]; }       /* 计数接近时取较短 lag */
}
if (best_cnt >= 5) achr = 3000.0f / best_lag;             /* 3000 = 60*50 */
```

两条设计依据：

1. **±1 聚簇**：lag 32/33/34 本属同一个周期峰，只在整数边界上抖动，必须合并成簇，否则众数会被切碎；
2. **计数接近时取较短 lag**：倍周期错锁的峰总是落在**更长**的 lag 上（§1.1 已证），所以在两簇势均力敌时取较短的那个。

## 4 最终判据结构（第五版完整口径）

| 环节 | 参数/规则 | 作用 |
|---|---|---|
| 预处理 | 去直流均值 → 4 点滑动均值 → 一阶差分 → 2 点均值 → 5 点汉明窗 `{41,276,512,276,41}/1146` → 阈值=绝对值均值 | Maxim 原生链路，不改 |
| 峰检测 | `n_min_distance = 8`，`maxim_find_peaks` + 谷点精确化 | 时域峰间隔法 |
| 自相关 | `AC_MW=16`，`AC_LAG_MIN=18`，`AC_LAG_MAX=80`，`AC_R_MIN=0.20`，生理区间优先 lag∈[26,40]（75~115 bpm），`AC_R_FULL=0.30` 兜底 | 主判据（PI≥2.5%） |
| lag 投票 | 15 窗环，±1 聚簇，`best_cnt≥5`，近计数取短 lag | 抑制邻近峰跳变 |
| 频域 | `SP_N=400`、`SP_K=6~20`（45~150 bpm）、`g_sp_q≥3` 才认、峰贴边（`best_k≤7` 或 `≥19`）作废、峰不贴边且峰/均值 ≥2 才更新 `sp_sm` | 主判据（PI<2.5%）+ 兜底 |
| 仲裁 | `pi_val ≥ 2.5f ? achr : spr` | 按灌注指数切换 |
| 时域平滑 | 15 点中位数 → 迟滞（差 >12 bpm 需连续 3 窗确认）→ `pr_slew` ±5 bpm/帧 | 抑制单窗突变 |
| SpO₂/PI | Maxim AC/DC 比值 + `uch_spo2_table[184]`，与 PR 判据完全独立 | 不受 PR 路径影响 |

`[AC]` 标识当前仍定义为"本算法比 Maxim 高 >15% 才点亮"，与"自相关优先"的新结构已不一致，属已知待改项（见 §9.6）。

## 5 频域实现（保留为兜底与交叉验证）

对去趋势后的 `x[i]`（17 点滑动均值高通，`x[i] = IR[i] − mean(IR[i−8…i+8])`）逐点 Goertzel：

```
for k = 6..20:                     // 45~150 bpm
    coeff = 2·cos(2πk/N)
    s1 = s2 = 0
    for i = 0..N-1:
        s0 = x[i] + coeff·s1 − s2;  s2 = s1;  s1 = s0
    mag[k] = s1² + s2² − coeff·s1·s2
取 mag 最大的 k，三点抛物线插值：
    δ = 0.5·(mag[k−1] − mag[k+1]) / (mag[k−1] − 2mag[k] + mag[k+1])
    f = (k + δ)·fs/N,   PR = 60·f
置信度：q = mag[k] / mean(mag)，q < 3 判不可信 → 退回自相关
```

- cos 表由递推生成（c0 = 0.99987663，s0 = 0.01570732），不占 flash 常量表；
- 全 float（F103 无 FPU，但 15 个 bin × 400 点 = 6000 次乘加，72 MHz 下可忽略）；
- 跨窗平滑 `sp_sm[k] = 0.7·sp_sm[k] + 0.3·mag[k]`，但**只在可信窗更新**（峰不贴边且峰/均值 ≥2），避免把错窗的谱污染进记忆（第一版引入，是原始版 0/3 的根因之一）。

### 5.1 为什么频域最终降级为兜底

频域对**频率**的估计好（相干积累 8 s ≈ 12 个周期），但对**波形态**敏感：压迫改变波形 → 谐波分布改变 → 主峰被带走（§3.3 的 PR≈60+7×PI）。所以只在灌注不足（PI<2.5%）、时域周期不可靠时启用。

## 6 分辨率极限（本章为定稿新增，用于解释"为什么 77 和 83 分不清"）

前面所有"锁 91 / 漂到 83 / 卡在 75"的现象，最终都归结为一条硬约束：**这套硬件 + 8 s 窗口能分辨的心率差是有限的**。下面把两个判据各自的分辨率算清楚。

### 6.1 频域：bin 宽 7.5 bpm

```
Δf = fs / N = 50 / 400 = 0.125 Hz
ΔPR = 60 × 0.125 = 7.5 bpm   ← 相邻 k 的 PR 间距
k = 12 → 1.500 Hz → 90.0 bpm
k = 11 → 1.375 Hz → 82.5 bpm
k = 10 → 1.250 Hz → 75.0 bpm
```

- 77 bpm = 1.283 Hz → k = 10.27；
- 83.5 bpm = 1.392 Hz → k = 11.13。

两者都落在 k=10 与 k=11 之间、且**没有跨 bin 边界**。这意味着频域在这两档之间唯一的区分手段是把整个峰判给 k=10 还是 k=11，误差本身就是半个 bin ≈ 3.75 bpm。

三点抛物线插值可以把 bin 内部的位置细化到 ~0.02 Hz（≈1 bpm），但**它只在峰被正确落到主 bin 时才有意义**；当峰被谐波或压力偏移推到相邻 bin，插值只会把错值算得更"精确"。这是插值法最容易被误用的地方。

### 6.2 自相关：lag 只能取整数

```
PR = 3000 / lag      (3000 = 60 × 50 Hz)
```

| lag | PR | 相邻 lag 的 PR 增量 |
|---|---|---|
| 32 | 93.8 | — |
| 33 | 90.9 | 2.9 |
| 34 | 88.2 | 2.7 |
| 36 | 83.3 | 5.0（跨 35） |
| 39 | 76.9 | 3.5 |
| 40 | 75.0 | 1.9 |

- **lag 差 1 点 ≈ 2~3 bpm**，这是自相关的天然量化误差；
- 76.9 与 83.3 只差 **3 个 lag 点（36 vs 39）**，90.9 与 76.9 差 6 个点（33 vs 39）；
- lag 域投票（§3.5）能做的只是"在这几个整数点里选最稳定的那个"，**不能创造比 1 个 lag 更细的分辨率**。

### 6.3 实测证据：83 那 25 帧不是心率、是判决

long2（4 分钟乱压）里最长的一段偏差：

```
212.01s  PI 7.3   PR 83
212.94~235.23s    PR 83 恒定 25 帧（PI 从 9.8 一路降到 1.0）
236.10s  PI 1.4   PR 78
237.07s  PI 1.6   PR 75     ← 1 秒内 83→78→75
```

`pr_slew` 已被设为 ±5 bpm/帧，所以 83→75 用了两帧走完。**1 秒内跳 8 bpm 不可能是真实心率变化**（人体心率不可能 1 秒降 8 次/分并保持），因此这 25 帧必是自相关锁到了 lag=36（83.3 bpm），而非 76.9 bpm（lag=39）。同轮次另有 132~139 s 的 7 帧尖峰（85→90→95→90→85→70），性质相同。

### 6.4 结论：±4 bpm 是这套配置的理论量级

| 判据 | 分辨率来源 | 量化误差 | 说明 |
|---|---|---|---|
| 频域 Goertzel | Δf = 0.125 Hz | **±3.75 bpm**（半个 bin） | 插值仅在峰位正确时有效 |
| 自相关 | lag 整数 | **±1.5 bpm**（相邻 lag 间） | 但峰位选错时误差达 3~7 bpm |
| 系统合成 | 两者叠加 | **±4 bpm 量级** | 与手机"误差 <3 次/分"同量级 |

要真正突破，只有加长窗口：

| 窗口 | N | Δf | ΔPR | 代价 |
|---|---|---|---|---|
| 8 s | 400 | 0.125 Hz | 7.5 bpm | 当前方案 |
| 16 s | 800 | 0.0625 Hz | 3.75 bpm | 启动 16 s；窗内可能跨 2 个心率值 |
| 24 s | 1200 | 0.0417 Hz | 2.5 bpm | 响应过慢，不适合实时显示 |

所以"把 SD 压到 1 以内且全压力区间都准"在本硬件（50 Hz）+ 8 s 窗口下**做不到**，这是分辨率问题而不是参数问题。定稿按此口径表述，不做超出物理极限的承诺。

## 7 PLL 72 MHz 的落地

原固件 HCLK = 8 MHz（未开 PLL），自相关单次 1,507,291 内核周期 = **187.8 ms**。开启 PLL 后所有与时钟相关的常量必须同步改，否则 SCL 会被拉到 450 kHz、串口波特率跑偏。

| 项目 | 8 MHz 原值 | 72 MHz 现值 | 说明 |
|---|---|---|---|
| 主频 | HSI 8 MHz | HSE 8 MHz × PLL9 = **72 MHz** | APB1 ÷2 = 36 MHz |
| Flash | 0 WS | **2 WS + 预取** | 72 MHz 必须 |
| `TICK_PER_MS` | 8011 | **72072** | DWT 每毫秒周期数 |
| I2C1 `CCR` | 80（50 kHz） | **360**（50 kHz） | `pclk1/(2×50k)` |
| I2C1 `CR2` | 8 | **36** | 单位 MHz |
| I2C1 `TRISE` | 9 | **37** | `pclk1/1MHz + 1` |
| USART2 `BRR`（9600） | 833 | **3750** | `pclk1/baud` |
| `uart_set_baud` 分母 | 8 000 000 | **36 000 000** | 同上 |
| `uart_read_timeout` 空转上限 | `ms×900` | `ms×900×(72/8)` | 轮询次数与主频成正比 |

实现要点：`clock_init()` 先启 HSE，**启振失败就退回 HSI 8 MHz**并让上述常量按 `g_hclk_khz/g_pclk1_khz` 运行时现算，避免"以为自己是 72 MHz"而把总线拉飞。

## 9 局限

1. **分辨率极限 ±4 bpm**：Δf=0.125 Hz（7.5 bpm/bin）与 lag 整数化（2~3 bpm/点）共同决定，见 §6。这是本配置的物理上限，不是调参能解决的。
2. **无运动伪差抑制**：压力突变/手指滑动的窗口，频谱能量会跑到 2.5~3.1 Hz（见 `_pbuf_ir3.txt`：k=21 占 17.4%、k=20 占 9.4%，基频仅 8%），PR 必然偏。手环/手表有加速度计做运动门控，本设计没有，只能靠 15 点中位数、迟滞与限速钝化。
3. **窗口 8 s + 平滑多级**：上电后首个有效值约 8 s，收敛还需 2~3 s，共约 11 s。
4. **`q` 门限是经验值**：3.0 来自本批实测（干净窗口 4.9~10.2、弱灌注 2.1~3.2、运动窗口 2.5~2.9）；换手指/换压力需重新标定。
5. **RED 通道坏字节修复未做**（IR 已做，末字节 0xFF 用上一样本低字节补齐）。
6. **`[AC]` 语义与现结构不一致**：当前仍按"本算法比 Maxim 高 >15%"点亮，而主判据已改为自相关优先，应改为"当前输出取自自相关路径"。
7. **上位机无"算法来源"指示**：需扩帧类型并同步改 `FRAME_LENGTHS`。
8. **波形帧节拍与上位机采样率不匹配**：真实帧率 ~14 帧/s（28 点/s），上位机按 50 Hz 处理，通带与 RMS 窗口实际拉长约 1.8 倍。
9. **`pr_val` 超时清除未做**：拿开手指后 PR 会残留旧值。
10. **诊断代码残留**：`led_probe()` 开机多耗 1.6 s，`i2c_scan`/`i2c2_diag`/`probe_i2c2_pull`/`dbg_edge[128]` 未清理，编译有 warning。

## 10 结论段（可直接引用）

> 本设计在 MAX30102 脉率测量中先后遇到三类系统性错误。其一是 Maxim 时域峰间隔法在低灌注下把重搏波计为独立心跳，读数偏高 15~20%；其二是在改用自相关作为替代判据后出现分频（倍周期锁定），把真实 88~93 bpm 报成 52.6 bpm，后者由手环三测（93/87/96）、手数（88）与干净窗口 DFT 主峰（1.50 Hz→90.0）三方参照证伪，其物理机制是心率变异使基频峰（lag=32，r=0.280）变宽变矮，而 2 倍周期处（r=0.226~0.235）仅低 0.05，"取全局最大"或固定门限 0.30 都会在此失效；其三是把主判据改为频域后出现的"压力耦合"——输出呈 PR ≈ 60 + 7×PI 的线性关系，证明频谱判据在测波形形态而非心跳周期。
>
> 据此确定最终结构：预处理沿用 Maxim 原生链路（去直流→4 点滑动均值→一阶差分→2 点均值→5 点汉明窗→自适应阈值），峰检测保持 `n_min_distance=8`；**当灌注指数 PI ≥ 2.5% 时以自相关为主判据，否则回退频域**；自相关段叠加 **lag 域投票**（15 窗环形缓冲、±1 聚簇取众数、`best_cnt ≥ 5` 才采用、两簇计数接近时取较短 lag，用以抵消"倍周期错锁总是落在更长 lag 上"这一偏差）；输出的 15 点中位数、迟滞（差 >12 bpm 需连续 3 窗）与 ±5 bpm/帧 限速保留。
>
> 验收改为"同一时刻手机对照"：手机测 77 bpm 后 10 秒内在同一手指上板采集。稳态 90 秒（cal77）三档给出 75.5±0.84 / 75.3±0.67 / 75.2±0.53，极差均为 2；4 分钟反复换压（long2，258 帧）全体均值 **76.91±3.28**，与手机差 **0.09 bpm**，三档均值 76.5/76.6/78.9 相差不到 2.4 bpm。这同时证明了两件事：一、自相关优先 + lag 投票消除了"PR 跟压力走"的耦合；二、输出精度已进入手机自带功能"误差 <3 次/分"的同量级。
>
> 定稿同时明确了本配置的能力边界：采样 50 Hz、窗口 400 点时，频域 Δf = 0.125 Hz（7.5 bpm/bin），自相关 lag 整数化带来每点 2~3 bpm 的量化误差，系统合成分辨率约 ±4 bpm，long2 中 25 帧锁 83（lag=36）后 1 秒回 75（lag=39）即为该极限的直接证据。要把 SD 压到 1 以内，只能把窗口加长到 16 s（分辨率 3.75 bpm），代价是启动延时翻倍且窗内可能跨两个心率值——因此本设计不再继续调参，而把"±4 bpm、启动 11 s、稳态 SD<1"作为交付指标。另配合 PLL 将 HCLK 提升到 72 MHz，并按 pclk1 现算 I2C 分频（CCR 80→360）、串口 BRR（833→3750）、DWT 毫秒标定（8011→72072）与 Flash 2 等待周期，单次"自相关+频谱"耗时由 311 ms（8 MHz 折算）降至 **43.2 ms**（3,113,085 内核周期），满足 1 Hz 实时调用。
