## 这份快照能说明什么

按时间顺序看，能还原硬件驱动层的搭建过程：先蓝牙，再 OLED，然后传感器与跌倒逻辑，最后才进入判据算法的改造。从 40 KB 到 98 KB 的那次跳变，是判据从"单路峰值"扩展到"自相关 + 频域 + 峰值三路并存"的节点。

## 不能说明什么

脉率判据的五轮演进主要在 `main.c` 内部迭代完成，**没有逐轮留档**。这五轮的设计思路、每轮失败的判据和修正理由写在定稿报告里：

```
01_报告/课设报告_MAX30102脉率判据五轮演进_定稿_20261116.md
```

所以准确的说法是：这份快照能证明硬件驱动的搭建顺序，但证明不了判据的五轮迭代过程。后者只有报告文字和每轮的实测数据，没有对应的源码。

## 使用注意

这些文件是历史备份，与 `CubeIDE工程/Src/main.c` 不构成可编译的工程——它们只保留 `.c` 文件本身，缺少当时配套的构建配置。仅供阅读和对照。
